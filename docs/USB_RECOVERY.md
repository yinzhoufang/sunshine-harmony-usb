# USB 映射恢复与升级

## 本版变化

修复 USB 重连或 HDC 转发规则丢失后，模式仍开启却无法访问应用列表的问题。正式中继每约 2 秒在独立线程中检查已选平板，只补缺失的七条映射，不覆盖冲突规则；切换模式时暂停修复，切回网络模式后停止恢复。不会新增开机自启动。

**从旧版升级：**结束当前串流，安装新版补丁，然后在设备中心关闭并重新开启一次鸿蒙数据线模式，使中继加载新逻辑。此操作会重启 Sunshine。平板桥无需重新安装，仍需保持分屏或悬浮窗可见。拔线导致的会话结束后，可能仍需手动重连 Moonlight。

验证：正式中继在七条映射全部被删除后约 **1.31 秒**自行补齐；135 项前端测试、10 项恢复专项测试以及既有模式切换 / 回滚 / 所有权测试通过。60.2 秒真实低负载观察中，双隧道失联样本 0、新增丢弃 0、中继积压最大 0 B。平均流量约 2.4 Mbps，**不作为本版 40 Mbps 满负载或操作延迟验收**。

## 排查顺序

1. 检查 USB 已连接并授权，设备中心选中原来的平板。
2. 解锁平板，打开 USB 隧道伴侣并以分屏或悬浮窗保持可见。
3. 等待自动恢复后，Moonlight 重连 `127.0.0.2`。
4. 若仍未就绪，在设备中心查看详细错误；映射冲突不会自动删除其他程序的规则。

恢复功能随受管理的中继运行，关闭面板窗口后仍可检查；退出中继或切回网络模式后不会继续恢复。它不会解除平板系统的后台冻结，也不会替用户重启已结束的串流会话。

## 开发测试

在控制面板源码目录运行 `python scripts/test_mapping_guard.py`。生产运行时通过 `--hdc` 和 `--transport-state` 成对传入已解析的 HDC 路径及受管理的模式状态文件。普通测试模式未传这两个参数时保持原行为。恢复线程与模式切换脚本使用同一个 Windows 全局互斥锁，HDC 子进程有超时，不在媒体事件循环内执行。
